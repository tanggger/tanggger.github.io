1. 优化概述与整体架构

1.1 优化管理器 (OptimizeManager)

所有优化遍均由 OptimizeManager 统一管理和调度。优化执行顺序如下：

1.2 设计原则

  • 迭代优化：许多优化会暴露新的优化机会，因此采用多轮迭代（如 Lvn + Gcm 循环 5 次）。
  • 清理遍协同：每个主要优化后都跟随 RemoveUnReachCode、CfgBuilder、RemoveDeadCode，确保 CFG 和 IR 的健康状态。
  • Pass 解耦：每个优化遍只负责单一职责，通过 Optimizer 抽象基类统一接口。

2. 控制流图构建 (CfgBuilder)

2.1 功能描述

CfgBuilder 负责根据基本块之间的跳转关系构建控制流图（CFG），主要维护以下信息：

  • 前驱 (Predecessors) 和 后继 (Successors) 列表
  • 支配关系 (Dominators)：直接支配者、支配边界
  • 支配树 (Dominator Tree)：用于 GVN 按支配序遍历

2.2 实现要点

  1. 后继关系推导：遍历每个基本块的最后一条指令：

    • JumpInstr：单后继
    • BranchInstr：双后继（True/False 分支）
    • ReturnInstr：无后继

  2. 支配关系计算：采用数据流迭代算法：

    • 初始化：每个块的支配者集合为所有块
    • 迭代：
    • 收敛后确定直接支配者（Immediate Dominator）

2.3 遇到的困难

  • 图不连通：某些基本块可能因优化变成孤立块，需在 CFG 构建后清理。
  • 循环处理：回边的存在使得支配关系计算需要多轮迭代才能收敛。

4. 死代码消除 (RemoveDeadCode)

4.1 功能描述

基于活跃性分析，删除结果未被使用且无副作用的指令。

4.2 核心算法

采用 Mark-Sweep 思想：

  1. 标记关键指令（Critical Instructions）：

    • ReturnInstr：函数必须返回
    • CallInstr：调用有副作用的函数（IO、修改全局变量）
    • StoreInstr：内存写入
    • BranchInstr / JumpInstr：控制流

  2. 反向传播：从关键指令出发，将其操作数（若为指令）也标记为活跃。

  3. 清扫：删除未标记的指令。

4.3 副作用函数识别

4.4 额外功能

  • 无用 Phi 删除：若 Phi 只有一个入边值，直接替换为该值。
  • 基本块合并：若块 A 只有一个后继 B，B 只有一个前驱 A，可合并。
  • 无用函数删除：若函数从未被调用（除 main 外），直接删除。

4.5 遇到的困难

  • 全局变量副作用传播：函数 A 调用 B，B 修改全局变量，则 A 也有副作用。需建立调用图进行传递闭包。
  • 条件删除的正确性：即使 branch 条件可常量折叠为 true，也不能直接删除 branch 指令，应替换为 jump。

6. Phi 指令插入 (InsertPhi)

6.1 功能描述

为 Mem2Reg 服务，在控制流汇聚点插入 Phi 指令。

6.2 算法步骤

  1. 收集定值点和使用点：遍历 alloca 的所有 user，分类为 Store（定值）和 Load（使用）。

  2. 在支配边界插入 Phi：

  3. 变量重命名：按支配树 DFS，维护值栈：

    • 遇到 Store：入栈
    • 遇到 Load：替换为栈顶值
    • 遇到 Phi（作为定值）：入栈
    • 离开块时恢复栈状态

6.3 遇到的困难

  • Phi 操作数顺序：Phi 的入边值与前驱块的顺序必须严格对应。
  • 未定义变量：若变量在某路径上未赋值就使用，栈为空，此时返回默认值 0。

7. Phi 指令消除 (RemovePhi)

7.1 功能描述

将 SSA 形式的 Phi 指令转换为并行复制（Parallel Copy），再转换为 Move 指令，以便后端生成 MIPS。

7.2 算法步骤

  1. Phi -> Parallel Copy：

    • 若块只有一个前驱：在前驱块末尾插入 ParallelCopyInstr
    • 若块有多个前驱：插入中间块，避免关键边问题

  2. Parallel Copy -> Move 序列：

    • 检测循环冲突（）：引入临时变量打破循环
    • 检测寄存器冲突：若 src 被后续 dst 覆盖，提前备份

7.3 实现代码片段

7.4 遇到的困难

  • 关键边：当一个块有多个前驱，且某前驱有多个后继时，不能直接在前驱块末尾插入 copy，需插入中间块。
  • MIPS 生成时机：RemovePhi 必须在 LLVM IR 输出后、MIPS 生成前执行，否则 Move 指令会污染 IR。

9. 全局代码移动 (GCM) 与循环不变量外提 (LICM)

9.1 功能描述

GCM 通过 Schedule Early + Schedule Late 算法，将指令移动到最优位置，自动实现：

  • 循环不变量外提 (LICM)：将循环内不变计算移到循环外
  • 代码下沉：将只在部分路径使用的计算下沉，减少寄存器压力

9.2 核心算法

  1. Schedule Early：根据操作数定义位置，确定指令最早可放置的块（必须被所有操作数支配）。

  2. Schedule Late：根据使用点，确定指令最晚必须放置的块（必须支配所有使用者）。

  3. 选择最优块：在 Early 和 Late 之间，选择 循环深度 (Loop Depth) 最小 的块。

10. 函数内联 (FuncInline)

10.1 功能描述

将被调用函数的代码体复制到调用点，消除函数调用开销，并暴露更多优化机会。

10.2 内联策略

10.3 内联步骤

  1. 分割调用块：将 Call 指令后的代码移至新的 Split Block。

  2. 克隆被调用函数：

    • 建立 Value Map（旧值 -> 新值）和 Block Map（旧块 -> 新块）
    • 形参映射到实参
    • 克隆所有基本块和指令

  3. 缝合 CFG：

    • 调用块末尾添加 jump 到 Callee Entry
    • Callee 的所有 return 替换为 jump 到 Split Block

  4. 处理返回值：

    • 单返回点：直接替换
    • 多返回点：插入 Phi 节点汇聚返回值

12. 寄存器分配 (RegisterAllocator)

12.1 功能描述

将 IR 虚拟寄存器映射到 MIPS 物理寄存器。

12.2 分配策略

按支配树遍历，采用线性扫描思想：

  1. 对每条定值指令，分配一个空闲寄存器
  2. 当变量最后一次使用后，释放其寄存器
  3. 跨块变量通过 InValueSet 和 OutValueSet 传递

12.3 遇到的困难

  • 跨块变量：进入子块时暂存当前寄存器状态，返回后恢复。
  • 寄存器不足：当可用寄存器耗尽时，需溢出到栈上（通过 $k0 临时寄存器中转）。
